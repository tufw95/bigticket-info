Privacy Policy

Last updated: August 13, 2026. Bigticket is a Chrome extension that assists users in a user-selected CTicket ticket workflow. Bigticket has no analytics, advertising, profile-sync, or payment-processing server.

Data handled by the extension

Bigticket can store the following data in chrome.storage.local inside the user's Chrome profile:

  • CTicket event URLs, sale schedules, ticket preferences, quantities, and optional budgets.
  • Optional Ticket Claimer fields entered by the user: name, email, phone number, and identity/passport number.
  • An optional Membership or presale access code.
  • A payment-method preference such as VietQR or card.
  • Operational state required to reconnect a user-managed CTicket tab.

Bigticket does not collect or store card numbers, expiry dates, CVV/CVC, bank credentials, OTP, 3DS data, queue tokens, or completed transaction details.

The extension also keeps a short-lived operational lease in chrome.storage.session while an event is armed. This lease contains event and sale timing, target tab/occurrence, ticket priorities and quantity, an optional budget, payment-method preference, and automation-state flags. It does not contain Ticket Claimer fields, Membership/presale codes, or payment credentials and is cleared when Chrome exits.

How data is used

  • Event and ticket preferences are used only to prepare and operate the CTicket event tab explicitly started by the user.
  • Ticket Claimer and presale fields are used only to fill matching forms in that managed tab.
  • The payment-method preference is used only to select CTicket's matching payment option and enter the ticket-hold screen. Payment credentials and the transaction remain under Chrome, CTicket/the payment provider, and the user.
  • While an event is running, the extension reads visible CTicket page state and same-origin CTicket event responses to detect sale timing, queue state, ticket availability, and checkout progress.
  • On CTicket event pages, a narrowly scoped main-world observer records only request timing, pending/completed state, transport, HTTP status, and a truncated CTicket endpoint path for event-status requests. It does not read request or response bodies, headers, Membership values, form fields, cookies, or queue tokens.

The automation content script is injected dynamically only into an enabled CTicket tab managed by Bigticket. A separate request-timing observer is registered at document_start only on CTicket event URL routes so it can see the page's earliest same-origin event-status request. It ignores queue, booking, payment, and other non-event routes even after an SPA route change, emits no personal or response-body data, and is ignored unless that tab is armed.

Bigticket does not read browsing activity outside CTicket event/workflow pages. Bigticket makes no update, analytics, or profile request to the developer's servers; Chrome Web Store provides extension updates.

When the user continues a CTicket form, the relevant form data is submitted to CTicket under CTicket's own privacy policy. Bigticket does not send saved user data to the Bigticket developer or to GitHub.

Sharing and sale of data

Bigticket does not sell user data. It does not use user data for advertising, creditworthiness, lending, or unrelated purposes. It does not share stored user data with third parties other than CTicket when the user uses the assisted workflow described above.

Retention and deletion

Stored data remains in the user's Chrome profile until the user clears it or uninstalls the extension. Users can:

  • remove an event to delete that event's plan and presale code;
  • use Xóa hồ sơ & mã presale to clear saved Ticket Claimer fields and the selected event's access code;
  • clear Bigticket extension data in Chrome; or
  • uninstall Bigticket to remove its local and session data from that Chrome profile.

Security and scope

Bigticket's website access is limited to https://cticket.vn/*. Sensitive profile state in chrome.storage.local is restricted to trusted extension contexts. The short-lived content-script lease is isolated in chrome.storage.session and excludes Ticket Claimer, presale, and payment-credential values.

CAPTCHA, OTP, seat/location selection, payment credentials, and the actual transfer/card submission remain user-controlled. The extension does not bypass queue tokens, authentication, or payment verification and does not execute remotely hosted code.

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.
